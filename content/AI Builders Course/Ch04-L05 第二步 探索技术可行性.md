# 第二步：探索技术可行性

## 我的理解

技术可行性探索的核心动作是：先让 GPT 列出多个实现方案及其优缺点，再结合自身场景选取最契合的方案，而不是被动接受 GPT 的第一个建议。本课揭示了一个关键陷阱：GPT 的知识截止日期会导致它对新版 API 和库一无所知，默认回退到旧接口从而生成无法运行的代码。破解之道是将最新 API 文档或示例代码放入 prompt，让 GPT 临时“学习”——这就是文档管理的直接起源。将 GenAI 调用方式从 GUI 迁移到 API，是本步骤最关键的能力跃升，它打开了以编程方式自动化任意 GenAI 任务的大门。

/**

* Classifies the email content using OpenAI's GPT API

* @param {string} emailContent - Text of the email to classify

* @returns {string} - GPT's response with the classification

*/

function classifyWithGPT(emailContent) {

// Replace with your OpenAI API key

const apiKey = 'YOUR_OPENAI_API_KEY';

// GPT-4 or GPT-3.5 endpoint settings

const endpoint = 'https://api.openai.com/v1/completions';

const prompt = Determine whether the following email is related to GenAI: "${emailContent}". Respond only "Yes" or "No".;

const requestData = {

model: 'text-davinci-003', // Adjust the model name accordingly

prompt: prompt,

max_tokens: 10,

temperature: 0.0 // Low temperature for more deterministic output

};

const options = {

method: 'post',

contentType: 'application/json',

headers: {

'Authorization': Bearer ${apiKey}

},

payload: JSON.stringify(requestData)

};

// Make the API request using UrlFetchApp

const response = UrlFetchApp.fetch(endpoint, options);

const jsonResponse = JSON.parse(response.getContentText());

// Extract the GPT classification from the response

return jsonResponse.choices[0].text.trim();

}

=======================================================

这里很容易就能发现问题：GPT 仍然在使用一个非常老旧的模型 GPT-3（text-davinci-003）。这会导致 API 不匹配，即便我们把模型名替换成 gpt-3.5-turbo，也仍然会报错。每个 GPT 模型都有一个知识截止日期。截至 2024 年 5 月，最新的 GPT 模型其知识截止日期为 2023 年 4 月。在那个时间点，关于使用 Google Apps Script 调用 GPT-4，甚至是 GPT-3.5 API 的在线文档或示例程序都还非常少。这就导致当下的 ChatGPT 对如何调用 GPT-4 API 知之甚少，并默认回到 GPT-3 上。

这是否意味着对于 GPT 不了解的库或 API，我们就无法借助 AI 辅助编程了呢？这听上去是个相当严重的限制！幸运的是，我们有一些实用而巧妙的技巧来绕过它。一种行之有效的方法是把 API 文档放进 prompt 中。这样 GPT 可以利用其推理与归纳能力，临时学习这些 API，并基于所提供的信息来编写程序。

It's easy to spot the problem here. GPT is still using a very old model, GPT-3 (text-davinci-003). This causes an API mismatch and will result in an error even if we replace the model name with gpt-3.5-turbo. Each GPT model has a knowledge cutoff date. The latest GPT model as of May 2024 has a knowledge cutoff date of April 2023. At that time, there were very few online documents or sample programs, especially those using Google Apps Script to invoke GPT-4 or even GPT-3.5 APIs. This results in the current ChatGPT not knowing much about how to invoke GPT-4 APIs and defaulting to GPT-3.

Does this mean we cannot use AI-assisted programming for any libraries or APIs that GPT doesn't know about? That sounds like a severe limitation! Fortunately, there are practical and clever tricks to get around this. One effective method is to include the API's documentation in the prompt. This way, GPT can use its inference and deduction capabilities to learn about the API on the fly and write programs using the given information.

We will explain the underlying principles and best practices in the next lesson. For now, we can unblock ourselves by going to the official Python library of OpenAI (it doesn't have to be JavaScript!) and including the content of an example file showing the API's usage in the prompt.
