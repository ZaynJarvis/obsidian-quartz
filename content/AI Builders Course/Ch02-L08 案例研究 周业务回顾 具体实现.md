# 案例研究：周业务回顾——具体实现

## 我的理解

WBR 实现过程展示了一套可复用的 AI 辅助编程工作法：从一个复杂 prompt 开始探索能力边界，遇到报错直接粘贴错误信息迭代，根据上下文是否“干净”来决定用对话还是编辑模式。最关键的判断力在于：何时用“对话”（上下文已合适，如直接粘贴错误信息），何时切换到“编辑”（上下文开始混乱，如多轮错误修复后手动清理 prompt）。最终代码起到“胶水”作用，将三步手工流程压缩为一步——这是原理而非技巧的胜利：对输出长度限制和上下文窗口的深层理解直接指导了任务拆解的时机。核心收获是：在 GenAI 时代，理解原理比记忆具体 prompt 更重要，学会“钓鱼”远胜于得到一条鱼。

构造 prompt——把调研中学到的东西用起来

构造 prompt 本身并不难。但有一个重要的决策点：要不要把问题拆解成更小的子问题，让 ChatGPT 更有可能一次性写出正确的程序。

=============================================

给初学者的小建议

写 prompt 是一门手艺活，做得越多，写得越好。

=============================================

但对初学者（以及面对不熟悉的 LLM）来说，常见做法是先从一个相对复杂的问题入手，如果 LLM 难以写出正确的程序（例如运行时 Python 抛出异常），再逐步拆解。这里我们会先把前两个任务（执行 SQL，以及把结果粘贴到 Excel）合在一起，因为它们在工作流中本来就是相邻的。

执行 SQL 并粘贴结果：这里我们以 SQLite 为例进行演示，但同样的方法可以轻松扩展到其他数据库引擎。注意在我们的场景里 SQL 查询是已知的。如果它比较短，可以直接放进 prompt 里；如果较长，可以用占位符来主动管理上下文窗口。只要你足够理解上下文窗口这个概念，这类优化技巧自然就会信手拈来。

小测验：尝试用一个 prompt 让 ChatGPT 同时完成这两个任务，记得使用编辑（editing）的方式。

示例 prompt

=============================================

I want to connect to a SQLite database events.db. And then execute some given SQL query (read from data.sql). After that I want to collect the result, and insert it into an Excel file WBR.xlsx. It has three tabs. I want to insert the result to the first tab (the name is Data, clean its content before insertion). Can you write a Python program for me?

=============================================

示例回复（这里只展示代码）

=============================================

import sqlite3

import pandas as pd

# Path to your SQLite database

db_path = 'events.db'

# Path to your SQL query file

sql_file_path = 'data.sql'

# Path to your Excel file

excel_path = 'WBR.xlsx'

sheet_name = 'Data'  # The name of the first tab where you want to insert the data

# Function to read SQL query from a file

def read_sql_query(file_path):

    with open(file_path, 'r') as file:

        return file.read()

# Read the SQL query

sql_query = read_sql_query(sql_file_path)

# Connect to the SQLite database

conn = sqlite3.connect(db_path)

# Execute the SQL query and fetch the data into a DataFrame

df = pd.read_sql_query(sql_query, conn)

# Close the database connection

conn.close()

# Write the DataFrame to the Excel file, replacing the content of the first tab

with pd.ExcelWriter(excel_path, engine='openpyxl', mode='a', if_sheet_exists='replace') as writer:

    df.to_excel(writer, sheet_name=sheet_name, index=False)

print("Data has been successfully inserted into the Excel file.")

import win32com.client as win32

def refresh_pivot_table_and_chart(excel_path):

excel = win32.Dispatch("Excel.Application")

excel.Visible = False

pivot_table = ws.PivotTables(1)

pivot_table.RefreshTable()

chart_sheet = wb.Sheets('Visualization')

chart = chart_sheet.ChartObjects(1)

chart.Copy()

# Save the chart as an image

image_path = 'chart_image.png'

chart_image = win32.Dispatch("Excel.Application").GetClipboardFormats()

if chart_image:

     chart_paste = win32.gencache.EnsureDispatch('Excel.Application')

     chart_paste.Visible = True

     ws_paste = chart_paste.Workbooks.Add().Sheets(1)

     ws_paste.Paste()

     ws_paste.Shapes(1).CopyPicture()

     ws_paste.Shapes(1).SaveAsPicture(Filename=image_path, Format=1) # Format=1 for PNG

wb.Close(SaveChanges=False)

excel.Quit()

return image_path

import win32com.client as win32

import os

def create_email_with_image(image_path):

outlook = win32.Dispatch('outlook.application')

mail = outlook.CreateItem(0)

mail.To = 'recipient@example.com'

mail.Subject = 'Data Analysis Update'

# Convert relative path to absolute path

abs_image_path = os.path.abspath(image_path)

print(f"Attempting to attach image at: {abs_image_path}")  # Debugging line

# Check if the file actually exists before trying to attach it

if not os.path.exists(abs_image_path):

     raise FileNotFoundError("The specified image file does not exist at the provided path.")

# Attach the image file and set a content ID

attachment = mail.Attachments.Add(Source=abs_image_path)

attachment.PropertyAccessor.SetProperty("http://schemas.microsoft.com/mapi/proptag/0x3712001F", "ChartImage")

# Use the content ID in the HTML body to reference the image

mail.HTMLBody = f"<p>Here's the updated chart from our analysis:</p><img src='cid:ChartImage'>"

mail.Display(True)  # Opens the draft email

# Path to your Excel file (adjust as necessary)

excel_file = 'WBR.xlsx'

# Assume chart_image_path has been created and returned from your chart exporting function

chart_image_path = 'chart_image.png'  # Ensure this is the correct path

# Create and display an email draft with the chart

create_email_with_image(chart_image_path)

识别常见卡点

不过有一个比较常见的坑需要注意。当我们使用 win32com 这个库时，必须使用绝对路径（例如 c:\code\chart.png），而不是相对路径（例如 chart.png）。ChatGPT 有时会写对，有时会写错。但我们随时可以问它“为什么我没看到图表导出来”，它会帮我们一起排查。GPT-4 仍然不是完美的，对于复杂任务，可能还是需要几轮对话或编辑才能搞定。

当然，遇到这种情况我们也可以选择把任务拆解开来。但就这个具体例子而言，我们应该能在 5 到 10 分钟内得到一个可以运行的程序——这比一位没有 AI 辅助的专业开发者要快得多。

Constructing the prompt – apply research learnings

The prompt construction is straightforward. But there is an important decision point: whether we want to decompose the problem into smaller subproblems so it'll be easier for ChatGPT to write the correct program in one shot.

This is because of the output limit we introduced in the previous lesson.

=============================================

Tips for beginners

Prompting is a craft. The more you do, the better you will get at it.

=============================================

But for beginners (and for unfamiliar LLMs), a common practice is to begin from a relatively complicated problem, and gradually decompose if the LLM struggles to write the correct program (e.g. when executing, python throws exceptions). Here we will begin with combining the first two tasks (SQL execution, and result pasting to Excel) together, because they are right adjacent in the workflow.

SQL execution and result pasting: Here we use SQLite as an example to showcase the usage. But it can easily extend to other database engines. Note that the SQL query is known in our scenario. We can include it in the prompt if it's short, or use a placeholder to intentionally manage the context window. Such optimization tricks should come naturally to you if you understand the concept of context window well enough.

import win32com.client as win32

import os

def create_email_with_image(image_path):

outlook = win32.Dispatch('outlook.application')

mail = outlook.CreateItem(0)

mail.To = 'recipient@example.com'

mail.Subject = 'Data Analysis Update'

# Convert relative path to absolute path

abs_image_path = os.path.abspath(image_path)

print(f"Attempting to attach image at: {abs_image_path}")  # Debugging line

# Check if the file actually exists before trying to attach it

if not os.path.exists(abs_image_path):

     raise FileNotFoundError("The specified image file does not exist at the provided path.")

# Attach the image file and set a content ID

attachment = mail.Attachments.Add(Source=abs_image_path)

attachment.PropertyAccessor.SetProperty("http://schemas.microsoft.com/mapi/proptag/0x3712001F", "ChartImage")

# Use the content ID in the HTML body to reference the image

mail.HTMLBody = f"<p>Here's the updated chart from our analysis:</p><img src='cid:ChartImage'>"

mail.Display(True)  # Opens the draft email

# Path to your Excel file (adjust as necessary)

excel_file = 'WBR.xlsx'

# Assume chart_image_path has been created and returned from your chart exporting function

chart_image_path = 'chart_image.png'  # Ensure this is the correct path

# Create and display an email draft with the chart

create_email_with_image(chart_image_path)

Identifying common blockers

There is a caveat that happens more often than others though. When we use the library win32com, we need to specify an absolute path (e.g. c:\code\chart.png) instead of a relative path (e.g. chart.png). Sometimes ChatGPT got this right, sometimes got it wrong. But we can always ask it why I didn't see the chart image exported. And it will help us figure it out. GPT-4 is still not perfect, and it may still take a few rounds of conversations / editing to make things right, especially for complicated tasks.

We can also decompose the task in this case. But for this specific example, we should be able to get a working program in 5-10 minutes, which is much faster than a professional developer (without AI).
